❯ If we wanna have the <h2> within each chapters (a.k.a. <dialog>) in different
  typefaces, should we do that by adding class to <h2> or tackle id thats
  already assigned to each <dialog>?

  Searched for 1 pattern (ctrl+o to expand)

⏺ Instructions understood.

  Both work, but you already have what you need: every <dialog> has a unique id
  (the-aspirin, beyond-the-box, faster-horse, …). You can reach each chapter's
  <h2> with a descendant selector, without changing your HTML:

  #chapter-one h2 {
          font-family: /* … */;
  }

  Read it as "any <h2> inside the element with id="chapter-one"."

  Why the id route is usually the better fit here:
  - No extra markup. A class on each <h2> would repeat what the id on the
    <dialog> already says.
  - It scales. If you later want other things in one chapter styled differently
    (paragraphs, <em>, links), you use the same pattern: #faster-horse p,
    #faster-horse em.

  One thing to watch: specificity. #id h2 is a strong selector, and it will beat
  a class-based rule like .title. That's fine as long as you know it. If a
  style "won't apply" later, specificity is the first thing to check.

  When a class makes more sense: if two or more chapters should share a
  typeface, a class like .serif-heading lets you reuse one rule instead of
  repeating it.

  References:
  - MDN: Descendant combinator
    (https://developer.mozilla.org/en-US/docs/Web/CSS/Descendant_combinator)
  - MDN: Specificity
    (https://developer.mozilla.org/en-US/docs/Web/CSS/Specificity)

❯ so currently we're using chapter titles as our id names. However, do you
  think we should be using chapter number as our id names? or does it matter?

⏺ Instructions understood.

  It doesn't matter to the browser; both work. It matters to you reading the
  code. I'd keep the titles.

  Why titles are the better choice:
  - Readable. #faster-horse h2 tells you which chapter you're styling. With
    #chapter-3 h2 you have to look up what chapter 3 is.
  - Stable. If you reorder or add chapters, number-based ids stop matching the
    order (or you rename them all, plus every button and CSS rule that points to
    them). A title stays correct wherever the chapter moves.

  If you do use numbers, don't start with a digit. id="3" is valid HTML, but #3
  isn't a valid CSS selector without escaping. Use something like chapter-3.

  Either way, check that your ids are:
  - unique on the page
  - lowercase and hyphenated (which yours already are)
  - matched exactly wherever they're referenced, like the buttons that open each
    <dialog>

  Reference: MDN: id attribute
  (https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/id)

❯ so for the dialog windows (a.k.a. chapters), we decided to keep the
  background white for better legibility and create a color bar that sticks to
  the top of the dialog pop-up window. The bar would also nest the current exit
  button, and a small eyebrow copy on the left side. In this case, should we
  use z-index and overlap that on the top? Or create a nav structure within the
  dialog window?

  Ran 1 shell command (ctrl+o to expand)

⏺ Instructions understood.

  Neither, quite. Wrap the bar's contents in their own element and make that
  element position: sticky. You already do this with the exit button (dialog >
  button in style.css:228 (style.css#L228)), so it's the same idea one level up.

  Why not overlap with z-index? Placing a bar on top with absolute or fixed
  takes it out of the flow. Your content would slide under it at the start, and
  you'd have to fake the space with padding. sticky keeps the bar in the flow at
  the top and only "sticks" once you scroll.

  Why not <nav>? <nav> is for groups of navigation links. A close button plus a
  label is really a header for that dialog, so <header> is the better fit
  semantically.

  The structure, roughly:

  <dialog id="example">
          <header>
                  <p>Eyebrow</p>
                  <button …>x</button>
          </header>
          …
  </dialog>

  Then think through these yourself:
  1. Which element gets position: sticky and inset-block-start: 0 now? (Your
     current button rule would move to the <header>.)
  2. Which flex property puts the eyebrow on the left and the button on the
     right?
  3. The bar needs its own background-color, or text will show through it while
     scrolling.
  4. Your dialog has padding-block. Does the bar sit flush to the top edge, or
     is there a gap? Negative margins or moving padding are options worth
     testing.

  You'd only reach for z-index if something inside the dialog (another
  positioned element) paints over the bar while you scroll. In that case, a
  small value like 1 on the header is enough.

  References:
  - MDN: position: sticky (https://developer.mozilla.org/en-US/docs/Web/CSS/posi
    tion#sticky_positioning)
  - MDN: <header>
    (https://developer.mozilla.org/en-US/docs/Web/HTML/Element/header)
  - Course site: Flexbox topic
    (https://typography-interaction-2627.github.io/topic/flexbox/)
